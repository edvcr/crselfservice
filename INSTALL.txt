COINSRAID HELP WIDGET - INSTALL GUIDE
=====================================

WHAT YOU GET
------------
A help widget for coinsraid.com: players browse help articles, search,
and start a live chat (Zendesk) without leaving the page. Hidden until
opened from a button on the site.


INSTALL - OPTION A: AUTO-UPDATING (recommended)
-----------------------------------------------
Nothing to upload. Add this one line to every page, next to the
existing Zendesk snippet:

   <script src="https://edvcr.github.io/crselfservice/dist/help-panel.min.js" defer></script>

Then make the site's "Help" button open the widget:

   CoinsraidHelp.open()

   Example:
   <button onclick="CoinsraidHelp.open()">Help</button>

Done. With this option the widget updates itself: improvements are
published to the same address, and the live site picks them up
automatically within about 10 minutes. No further developer work is
ever needed.


INSTALL - OPTION B: SELF-HOSTED COPY
------------------------------------
If you prefer the files to live on your own servers, upload both
files from the dist folder to the SAME directory, e.g. /help/ :

  help-panel.min.js     the widget itself
  help-articles.json    offline copy of the help articles (fallback)

Then add the script tag with your own path:

   <script src="/help/help-panel.min.js" defer></script>

and wire the Help button the same way as in Option A.
Note: with this option every widget update must be re-uploaded
manually. Use Option A unless there is a policy reason not to.


HOW IT BEHAVES
--------------
- Nothing is visible until the first CoinsraidHelp.open() call. There
  is no permanent corner button, since the site has its own Help
  button. To show one anyway, set before the script tag:
     <script>window.CRH_LAUNCHER = true;</script>
- The minimize button (-) leaves a small round help icon in the corner
  so the player can come back quickly. The X hides everything again.
- "Live Chat" opens the Zendesk chat in place of the article panel.
  The standard Zendesk launcher bubble is hidden automatically -
  the widget is the single entry point for support.
- If an agent replies while the chat is closed, the player gets a
  small toast notification and the help icon appears in the corner
  with an unread counter, even when the corner button is switched
  off. Both disappear once the messages have been read.
- Works on desktop, tablet and mobile (full screen on phones).

Other available calls, if ever needed:
  CoinsraidHelp.close()    close everything
  CoinsraidHelp.toggle()   open/close
  CoinsraidHelp.chat()     jump straight to live chat
  CoinsraidHelp.login()    retry chat sign-in (see next section)
  CoinsraidHelp.article(id) open a help article in a pop-up
  CoinsraidHelp.logout()   sign the player out of chat


AUTHENTICATED CHAT
------------------
Without this, every chat visitor becomes a new anonymous user in
Zendesk and is asked for a name. With it, chats attach to the real
player record (matched by the CoreX user ID), agents see who they are
talking to, and signed-in players are not asked for name or email.

On coinsraider.us (staging) and coinsraid.com (prod) this works with
NO extra site code. The widget reads the player's sign-in cookie
(qp_token) and asks the GiG API for a chat token (POST, body
{"provider":"zendesk"}):

  coinsraider.us  ->  https://stg-api-d.gigmagic.io/.../externalServices/getChatToken
  coinsraid.com   ->  https://api-d.gigmagic.io/.../externalServices/getChatToken

Subdomains (e.g. www.) count as the same site. GiG signs the token
with the matching Zendesk key for that environment.

It also follows the site's own sign-in state: when a player signs
out, or a different player signs in on the same browser, the widget
signs the chat out the next time a page loads or chat is opened, so
nobody sees the previous player's conversation. Players who are not
signed in chat anonymously, with no errors.

Optional calls if the site wants instant updates without waiting for
a page load:
   CoinsraidHelp.login()    after a player signs in
   CoinsraidHelp.logout()   after a player signs out

Other domains (custom setups only): set the token source yourself
before the widget script tag. This overrides the built-in behaviour.

   <script>window.CRH_AUTH_URL = "/api/zendesk/messaging-jwt";</script>

The endpoint is fetched with cookies (credentials: "include") and may
return either the raw JWT as text or JSON like {"jwt": "..."}. The
fields jwt, token, chatToken and accessToken are all accepted, also
inside a {"res": ...} wrapper.

If the endpoint needs a POST, or an authorization header, set an
object instead of a plain URL:

   <script>
   window.CRH_AUTH_URL = {
     url: "https://api.example.com/externalServices/getChatToken",
     method: "POST",
     headers: { Authorization: "Bearer " + playerAccessToken }
   };
   </script>

POST requests send an empty JSON body by default. Set body to send
something else. Alternatively, set a function that returns the JWT
(or a promise of it):

   window.CRH_GET_JWT = function () { return somePromiseOfJwt; };


HELP ARTICLE LINKS IN CHAT
--------------------------
When an agent or the AI agent sends a Help Center link in the chat
(coinsraid.com/#article-<id>, or a Zendesk Help Center article
link), clicking it opens
the article in a pop-up instead of a new tab on the Zendesk Help
Center. On desktop it sits next to the open chat (the chat stays
visible and usable); otherwise it is centred, and on phones it is full
screen. The minimise button shrinks it to a small tab with the article
title; click the tab to bring it back. Links inside the article open
in the same pop-up. Esc, the X or a click on the dimmed page closes it.
"Back to chat" closes it; "Chat with us" (when no chat is open) opens
the chat. Other links still open normally.

Preferred link format for chat replies and macros (hides Zendesk):
   https://coinsraid.com/#article-29414532464028
In the chat it opens the pop-up on the current page (staging or prod).
Opened anywhere else (email, copied link) it goes to coinsraid.com
with the article already open in the pop-up. The number is the
article ID from its Help Center address.

From the site's own code the pop-up can also be opened with:
   CoinsraidHelp.article(29414532464028)


FOOTER LINKS
------------
Plain links are enough. Clicking one opens the help panel or the
article pop-up on the current page, every time it is clicked, without
leaving the page. The same addresses also work when opened directly.

Support column:
   <a href="#help">Help &amp; Support</a>
   <a href="#article-29414532370460">FAQ</a>
   <a href="#article-29414532464028">How to Redeem Prizes</a>
   <a href="#article-29414547757724">Verify Your Account</a>

Legal / responsible play area:
   <a href="#article-29414532635676">Responsible Social Play</a>
   <a href="#article-29414547615388">Free Entry (AMOE)</a>

"Help & Support" opens the help panel. Live chat is one tap away
inside it ("Ask for help"), so no separate "Contact Support" link
is needed. #support works the same as #help.

Full addresses, for emails or other sites:
   https://coinsraid.com/#help
   https://coinsraid.com/#article-29414532370460   (FAQ)


UPDATING ARTICLES
-----------------
Articles are loaded live from the Help Center when it is reachable.
The help-articles.json file is only a backup used when it is not.
To refresh the backup after articles change in Zendesk, ask for a new
help-articles.json and replace the old file. Nothing else to do.


ANALYTICS (optional)
--------------------
The widget pushes events into window.dataLayer (Google Tag Manager):
  help_opened, help_closed, help_search,
  help_article_viewed, help_chat_opened
To see them in GA4, add a GTM Custom Event trigger matching help_.*
and map the parameters. If there is no GTM on the page, the events
do nothing and cause no errors.


WHAT NOT TO INSTALL
-------------------
Only the two files listed above go on the website. Everything else in
the repository is for demo and preview purposes - do NOT put it on
the live site:

  index.html        demo page with device tabs (preview only)
  share.html        demo page (preview only)
  README.md         repository notes
  INSTALL.txt       this guide

Notes:
- The demo pages contain a purple "Open Help Widget (test)" button.
  That button does NOT exist in dist/help-panel.min.js - the
  production file has no test code at all, so there is nothing to
  disable or remove. Just use the file as is.
- Do not copy the script tag from the demo pages. Use only the
  script tag shown in the INSTALL section above.
- The demo pages have articles baked inside them; the production
  widget instead loads articles live (with help-articles.json as
  fallback). This is expected.
